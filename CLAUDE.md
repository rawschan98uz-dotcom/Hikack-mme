## Что это за проект
LMS/CRM для учебных центров: лиды, студенты, группы, посещаемость, оплаты, зарплаты, Telegram-бот.
- **Backend:** Django REST Framework — `app/backend/` (приложения `accounts`, `api`, `crm`, `finance`, `operations`, `org`, `config`). База — SQLite (`app/backend/db.sqlite3`).
- **Frontend:** Vue 3 + TypeScript + Vite + Pinia — `app/frontend/`.
- Интерфейс на русском/узбекском, данные клиентов реальные — не удаляй и не «чисти» базу без прямого разрешения.

## Как запускать и проверять (этот компьютер)
Проект лежит в `D:\Projects\HiJackLMS`. Десктоп-версия (`AppData\Local\Programs\HiJack-LMS`) здесь **не установлена**, поэтому `sync-app.ps1` здесь не используется (в нём пути другого компьютера — не трогай его).

- Сервер: `run-backend.bat` → http://127.0.0.1:8000 (Python из `app\backend\.venv`)
- Интерфейс в режиме разработки: `run-frontend.bat` → http://localhost:5173

Полная проверка одной командой — `/check` (`.claude/commands/check.md`). Сейчас: 78 автотестов, все проходят.

После **любой** правки кода, прежде чем говорить «готово»:
1. Backend изменён → `app\backend\.venv\Scripts\python.exe manage.py check` (из `app/backend`).
2. Модели изменены → `makemigrations` + `migrate`, сообщи владельцу, что поменялась структура базы.
3. Frontend изменён → `npx vue-tsc -b --noEmit` в `app/frontend` (проверка ошибок). Сборку `npm run build` делай только если нужно обновить `dist/`.
4. Есть тесты рядом с изменённым кодом → запусти `manage.py test <приложение>`.
5. Если можно — открой страницу в браузере и убедись, что всё работает. Напомни нажать **Ctrl + F5**.

## Правила бизнес-логики
- **10 непреложных решений владельца** — раздел 1 в `HIJACK_LMS_FULL_HANDOFF_REPORT.md`. Не оспаривай и не меняй их.
- Часовой пояс везде `Asia/Tashkent` (UTC+5), валюта UZS.
- Почти все данные изолированы по `company` — каждый запрос обязан фильтровать по компании пользователя.
- Членство студента в группе — поле `Student.group`; `GroupEnrollment` — только история.
- Студентов не удаляем, а архивируем (`status = LEFT`).
- Пользователь **никогда** не может удалить свой аккаунт (backend → 400, кнопка скрыта в профиле).
- Удалять сотрудников и учителей может только роль `CEO` (или superuser); для остальных и на своей карточке кнопки удаления скрыты.
- Деньги (балансы, оплаты, зарплаты) — меняй особенно осторожно, объясняй владельцу последствия.
- Токены и секреты (`.env`, `notifications.json`) не коммить и не показывай.
