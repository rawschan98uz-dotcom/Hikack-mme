## Что это за проект
LMS/CRM для учебных центров: лиды, студенты, группы, посещаемость, оплаты, зарплаты, Telegram-бот.
- **Backend:** Django REST Framework — `app/backend/` (приложения `accounts`, `api`, `crm`, `finance`, `operations`, `org`, `config`). База — SQLite (`app/backend/db.sqlite3`).
- **Frontend:** Vue 3 + TypeScript + Vite + Pinia — `app/frontend/`.
- Интерфейс на русском/узбекском, данные клиентов реальные — не удаляй и не «чисти» базу без прямого разрешения.

## Как запускать и проверять (этот компьютер)
Проект лежит в `D:\Projects\HiJackLMS`. Десктоп-версия (`AppData\Local\Programs\HiJack-LMS`) здесь **не установлена**, поэтому `sync-app.ps1` здесь не используется (в нём пути другого компьютера — не трогай его).

- Сервер: `run-backend.bat` → http://127.0.0.1:8000 (Python из `app\backend\.venv`)
- Интерфейс в режиме разработки: `run-frontend.bat` → http://localhost:5173

Полная проверка одной командой — `/check` (`.claude/commands/check.md`). Полный прогон автотестов идёт около 20 минут — во время работы запускай тесты изменённого приложения, полный прогон — в конце.

После **любой** правки кода, прежде чем говорить «готово»:
1. Backend изменён → `app\backend\.venv\Scripts\python.exe manage.py check` (из `app/backend`).
2. Модели изменены → `makemigrations` + `migrate`, сообщи владельцу, что поменялась структура базы.
3. Frontend изменён → `npx vue-tsc -b --noEmit` в `app/frontend` (проверка ошибок). Сборку `npm run build` делай только если нужно обновить `dist/`.
4. Есть тесты рядом с изменённым кодом → запусти `manage.py test <приложение>`.
5. Если можно — открой страницу в браузере и убедись, что всё работает. Напомни нажать **Ctrl + F5**.

## Финансы — как устроены (решения владельца, октябрь 2026)
Устройство — как бумажная тетрадь: **прошлое записано и не пересчитывается**. Никогда не вычисляй прошлые суммы из сегодняшних настроек (цены, процента, расписания) — это была главная дыра.
- **Строка месяца** (`finance.StudentCharge`, код — `finance/charges.py`): ученик + его месяц + сумма. Месяц ученика идёт от даты прихода (пришёл 17.09 → 17.09–17.10). Сумма пишется в первый день месяца по цене этого дня и не меняется.
- **Оплата закрывает самую старую неоплаченную строку** (`PaymentAllocation`). Долг — незакрытые строки, сумма точная. Предоплата — не больше 24 месяцев вперёд, по цене на день оплаты.
- **Цена курса действует с даты** (`crm.CoursePrice`, `crm/pricing.py`). Меняет только CEO, всё в журнал. «Исправить» ошибочную цену переценивает только неоплаченные строки.
- **Скидка** — в строке, не больше 50% цены месяца; скидка — не деньги.
- **Учитель** получает процент только с оплаченных строк и только за проведённые уроки (`finance/payroll.py`): 10 учеников, заплатили 7 → к выплате за 7, остальное — когда заплатят. Процент запоминается в день урока.
- **Три окна на одни записи**: ученический учёт (строки, отчёт «Месяцы учеников»), учёт владельца (P&L по дате денег: долг сентября, оплаченный в декабре, = приход декабря), зарплатная ведомость.
- **Дата окончания группы — только план**, уроки не блокирует. Дату старта ученика после начисления месяцев меняет только CEO.
